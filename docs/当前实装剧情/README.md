## 当前剧情系统的实际结构

- 剧情的先后顺序、状态转换和触发条件由 Java 编写。
- 公告、私信和 NPC 对话文案保存在 JSON 中，修改文案不会改变剧情顺序。
- 每个阶段有一个独立的 Java 剧情类；目前分别为 `OpeningStory` 和 `AfterdreamStory`。
- 公告、NPC 交互、私信阅读、进入地点和使用物品等事件，统一先交给剧情管理器，再由当前阶段处理。
- 世界剧情与全部玩家的个人剧情状态统一保存在世界存档的 `data/dreamingfishcore/story/story_state.json` 中。
- 阶段不会根据任务完成比例自动切换，只能由服主手动推进。

当前的阶段切换命令为：

```text
/dreamingfish story stage set dreamingfishcore:afterdream
```

## 三次早期逆转疗程与随访（已实装）

二级感染不再停在“无药可治”。完整流程如下：

| 项 | 实际行为 |
| --- | --- |
| 适用对象 | 已完成首次接待、感染等级为二级的玩家（一级仍走一瓶基因复苏试剂） |
| 触发入口 | 在逐光会医疗接待点与江晚交互；结果对话说明药剂无效后，下一次交互开始第一次治疗 |
| 疗程节奏 | 三次治疗，每次间隔 1 个**剧情活动日**（24,000 tick，仅在线累计）；间隔不能压缩 |
| 治疗形式 | 院内治疗：由江晚在接待点执行，不消耗玩家物品，也不依赖药剂使用事件 |
| 终检 | 第三次治疗之后再次交互即完成终检：感染读数清零、解除感染状态 |
| 随访 | 终检后第 3 天与第 7 天，白芷发私信提醒；到接待点与白芷交谈即完成复核 |
| 随访后果 | 缺席或延后**没有任何惩罚**，只记录事实（与“无随机失败”原则一致） |
| 面具有序 | 疗程期间若面具已可领取，仍按原有会话规则发放，不阻塞疗程 |

相关文案在 `config/dreamingfishcore/data/story_text.json`，私信在 `config/dreamingfishcore/data/npc_messages.json`。

## 线索掉落（已实装）

12 条线索的文案与掉落规则见 [07-丧尸线索掉落文案](../story/07-丧尸线索掉落文案.md)，
目前已实装的部分为：

| 项 | 实际行为 |
| --- | --- |
| 触发入口 | 被真人玩家击杀的普通丧尸（僵尸、尸壳）与攻城丧尸 |
| 概率 | 普通丧尸与攻城丧尸各 0.01%；由 `config/dreamingfishcore/clue_drop.json` 控制（小数百分比，可整体关闭） |
| 掉落物 | 一张绑定线索编号的残页物品，右键后记入随记本 |
| 去重 | 玩家已收录的线索不再掉落；收齐后不再掉落 |
| 身份 | 幸存者与感染者完全一致，无身份专属线索 |
| 内容来源 | 首次开服写入 `config/dreamingfishcore/data/fragment_data.json`，之后可编辑 |
